# 《夜语村》—— 单机多人狼人杀（Local LLM Bot）游戏设计文档

## 1. 游戏概述

### 1.1 概念
一款单机运行的"狼人杀"游戏。人类玩家与若干由本地 Ollama LLM 驱动的 bot 同桌。每个 bot 拥有独立的**性格档案（Personality）**和**记忆档案（Memory）**，使每一局游戏产生不可预测的社交推理体验。玩家需要通过观察、提问、套话来识别狼人；bot 之间也会互相试探、结盟、欺骗。

### 1.2 设计目标
- **单机隐私**：所有 AI 推理本地完成（Ollama），无联网依赖。
- **可塑性**：玩家可自由创建/删除性格档案，决定每个 bot 的说话风格与行为模式。
- **连续性**：bot 的 memory 跨局保留（适当摘要），让 bot "记得"上一局谁骗过它。
- **对话驱动**：白天是开放式自由活动时间，对话是核心玩法载体。
- **可配置**：人数、角色板子、LLM 模型、轮次上限均可调。

### 1.3 非目标
- 不做实时语音/3D 画面（文本 + 简单表情/动作描述）。
- 不追求竞技平衡到极致，优先娱乐性与戏剧性。

## 2. 技术架构

### 2.1 总体结构

```
┌─────────────────────────────────────────────┐
│  Browser (HTML5 单页应用, 静态托管)            │
│  - 大厅 UI / 游戏 UI / 性格编辑器               │
└──────────────┬──────────────────────────────┘
               │ fetch (REST/JSON)
┌──────────────▼──────────────────────────────┐
│  Static Content Server (Node/Python)          │
│  - 托管前端静态文件                             │
│  - 提供少量 Game API：                         │
│    /api/personalities  (CRUD)                 │
│    /api/game           (开局/行动/对话)         │
│    /api/ollama         (LLM 代理)             │
│  - Personality 文件 & Memory 的持久化读写        │
└──────────────┬──────────────────────────────┘
               │ HTTP localhost:11434
┌──────────────▼──────────────────────────────┐
│  Ollama (本地 LLM, e.g. qwen2.5:7b)          │
└─────────────────────────────────────────────┘
```

### 2.2 关键决策
- **静态服务器 + 轻量 API 层**：前端是纯 HTML5/JS，但游戏状态（memory、personality 文件）需要服务端文件读写，因此有一个极薄的后端（~300 行）。它不做任何 AI 逻辑，只做文件 I/O 和 Ollama 代理。
- **LLM 调用全部走服务端代理**：避免浏览器 CORS 问题，且便于做超时控制、重试、prompt 日志。
- **模型分层**（可选优化）：bot 闲聊用小模型（3B），关键投票/身份推理用大模型（7B/14B），降低延迟。

## 3. 数据文件设计

### 3.1 Personality 文件（持久化，JSON）

每个 bot 一个文件，位于 `/personalities/*.json`：

```json
{
  "id": "luna_the_shy",
  "name": "露娜",
  "display_name": "露娜（安静的观察者）",
  "version": 1,

  "speech_style": {
    "verbosity": "low",            // low | medium | high —— 话多程度
    "tone": "温柔、迟疑、很少主动攻击别人",
    "catchphrases": ["唔……", "我不太确定……", "让我想想……"],
    "sentence_length": "short",    // short | medium | long
    "emoji_usage": "rare",         // never | rare | often
    "dialect_or_quirk": "句尾偶尔带省略号"   // 语言习惯/口癖
  },

  "behavior": {
    "proactiveness": "passive",    // passive | balanced | aggressive —— 主动发言倾向
    "suspicion_style": "cautious", // cautious | direct | theatrical
    "small_actions_pool": [        // 小动作库，自由活动时随机/情境触发
      "轻轻搅动着面前的咖啡",
      "下意识地摸了一下耳垂",
      "目光快速扫过每个人的脸"
    ],
    "habitual_gesture": "思考时会用笔尖点桌面",
    "lying_tells": [               // 说谎时的"破绽"（玩家可观察！）
      "语速突然变快",
      "避免直视提问者的眼睛"
    ]
  },

  "social": {
    "openness_to_player": "wary",  // friendly | neutral | wary —— 对玩家的初始态度
    "grudge_holder": true,         // 记仇（memory 中负面事件权重大）
    "leadership_tendency": "follower"  // leader | follower
  },

  "meta_prompt_hint": "你是一个内向但观察力敏锐的玩家。你倾向于在确信时才发言，一旦被逼问会变得防御。"
}
```

**设计要点**：
- 玩家可在大厅的"性格编辑器"中以表单方式创建/编辑/删除这些文件。
- 开局时玩家为每个 bot 槽位指派一个 personality；系统校验同名角色不可重复（或允许重复但建议不同）。
- `lying_tells` 是本游戏的核心观察点：狼人 bot 撒谎时，LLM 被指示穿插这些破绽文本，玩家观察模块可以高亮它们。

### 3.2 Memory 文件（内存态 + 可选跨局持久化）

每个 bot 一个 memory 对象，**存在于服务端内存中**，对玩家不可见（这是"脑内信息"）。结构：

```json
{
  "bot_id": "luna_the_shy",
  "current_game": {
    "role": "werewolf",
    "teammates": ["brash_marcus"],
    "known_info": [
      {"day": 1, "fact": "验人结果：Kai 是村民", "source": "seer_vision", "reliability": "certain"},
      {"day": 2, "fact": "Marcus 白天一直带节奏踩 Yuki", "source": "observation", "reliability": "suspected"}
    ],
    "suspicions": [
      {"target": "Yuki", "level": 0.7, "reason": "她回答问题时转移话题"}
    ],
    "alliances": [{"with": "Kai", "type": "tentative_trust"}],
    "my_plan": "今晚和 Marcus 商量刀 Kai，他是场上最敏锐的村民",
    "deception_notes": "我对 Kai 表现得友好，他尚未怀疑我"
  },
  "cross_game": {
    "summary": "上局（3天前）：我（露娜）作为狼人赢了；Kai 第二晚差点识破我，这局对他保持警惕。Marcus 上局跳预言家骗过了全场，信誉存疑。",
    "relationship_ledger": [
      {"player": "Kai", "net_trust": -0.3, "note": "两次对局中他都差点看穿我"},
      {"player": "Marcus", "net_trust": -0.1, "note": "能力强但不可轻信"}
    ]
  },
  "self_model": "我在这个游戏里的风格：话少但记性好，被冤枉时会情绪化",
  "token_budget": 1200
}
```

**Memory 管理规则**：
- **写入时机**：每次 bot 行动/对话后，LLM 同时输出一段"记忆更新"（增量），由服务端 merge。
- **摘要策略**：当 `current_game.known_info + suspicions` 超过 token 预算（默认 1200 token），触发压缩：保留所有 `certainty: certain` 的事实和最近一天的内容；对旧的 `suspected` 条目由 LLM 合并成一段概括（"第1-2天我主要怀疑过 Yuki 和 Marcus，后来发现 Marcus 是我队友"）。
- **跨局**：游戏结束时，LLM 生成 ≤150 字的跨局总结写入 `cross_game.summary`；`current_game` 清空。`relationship_ledger` 按玩家名累计信任度（-1 ~ +1）。
- **安全**：memory 绝不进入其他 bot 的 context；狼人队友名单只出现在狼人自己的 memory 里。

## 4. 角色系统

### 4.1 标准角色板子（默认 9 人局）

| 角色 | 数量 | 能力 |
|------|------|------|
| 狼人 Werewolf | 2 | 每晚共同选择一名玩家袭击；白天伪装成村民 |
| 预言家 Seer | 1 | 每晚查验一名玩家身份（好/狼） |
| 女巫 Witch | 1 | 一瓶解药（救被袭击者）、一瓶毒药（毒任意一人），各限一次 |
| 猎人 Hunter | 1 | 被投死或被袭击死时可开枪带走一人 |
| 村民 Villager | 4 | 无夜间能力，靠白天推理 |

### 4.2 扩展角色（后续版本）
- **守卫 Guard**：每晚守护一人（不可连续守同一人）。
- **白痴 Fool**：被投死时翻牌免死，但失去投票权。
- **白狼王 / 狼美人**：增强狼人方的戏剧性。

### 4.3 角色分配
- 开局由 Game Master 服务端逻辑随机分配，**通过 system prompt 告知每个 bot 自己的角色**。
- bot 的 personality 文件中**不包含**角色倾向——同一个人格可能这局是狼人、下局是预言家，性格与身份的错配本身产生趣味（"那个害羞的露娜居然在悍跳预言家？"）。

## 5. 游戏流程状态机

```
LOBBY → ROLE_REVEAL → DAY_PHASE ⇄ NIGHT_PHASE → GAME_OVER
                          ↑           ↓
                    (vote/lynch)  (werewolf kill,
                                  seer check, witch)
```

### 5.1 阶段 0：大厅（Lobby）
1. 玩家选择/创建对局配置：总人数（6–12）、角色板子、每个 bot 槽位绑定的 personality 文件、LLM 模型选择。
2. 前端校验：personality 文件存在且未损坏；人数与角色板子匹配。

### 5.2 阶段 1：角色揭示
- 屏幕显示玩家自己的角色卡（带简短能力说明）。
- GM 系统向每个 bot 发送私密 system message："你是本局的【狼人】，你的狼队友是 Marcus……"
- **开场白**：每个 bot 用一句话介绍自己进场（根据其 personality 生成），营造圆桌氛围。

### 5.3 阶段 2：白天 —— 自由活动时间
这是本游戏区别于传统狼人杀的核心创新：**没有固定发言顺序的死板轮流，而是动态行动队列**。

**行动队列机制**：
- GM 维护一个行动队列。每个 bot 根据其 `proactiveness` 有初始"行动冲动值"：
  - `aggressive`：每轮至少主动行动 2–3 次
  - `balanced`：1–2 次
  - `passive`：0–1 次，多在被问到时回应
- 每个"回合步"中，GM 按以下逻辑选出下一个行动者：
  1. 若有未回应的提问（bot 被问或玩家被问），优先回应者。
  2. 否则按冲动值加权随机选一个 bot 发起动作。
  3. 玩家随时可插话（见 5.4）。
- 单个 bot 的动作从以下类型中由 LLM 自主选择：
  - **小动作/表情**（无对话，纯描述文本，如"Marcus 靠在椅背上，环视全场"）
  - **向某玩家/bot 提问**（可以是试探、闲聊、质疑）
  - **发表看法**（"我觉得昨晚的事情很蹊跷……"）
  - **响应/反驳**别人的话

**玩家观察**：玩家可点击任一 bot 的头像"观察"，看到该 bot 最近的表情/小动作描述；若该 bot 正处于说谎状态（狼人伪装），其 `lying_tells` 破绽会以高亮显示（如"⚠ 语速突然变快"）——这是玩家推理的核心信息来源。

**进入黑夜的触发条件**（满足任一）：
- 全场无任何 bot/玩家再发起提问，且 GM 判定"话题枯竭"（连续 N=3 个行动步都是小动作/无实质对话）。
- 总对话轮数达到上限（默认 50 条对话，可在配置中调整）。
- 玩家手动点击"提议进入黑夜"，若 2 个以内 bot 反对（由 LLM 根据 personality 判断是否还想发言）则通过。

### 5.4 玩家行动选项（白天）
轮到玩家时（或玩家主动插话时），UI 提供：
1. **观察 [bot]**：查看该 bot 最近的动作/表情描述。
2. **向 [bot] 提问**：自由文本输入；也可以选择快捷模板（"你昨晚为什么那么安静？""你怀疑谁？"）。
3. **发表看法**：自由文本，所有 bot 可见。
4. **小动作**：从列表选一个表情/动作（微笑、皱眉、记录笔记……），bot 会注意到并可能回应。
5. **提议进入黑夜**。

玩家的每次发言同样会被 LLM "听见"并进入各 bot 的 memory 与后续 prompt。

### 5.5 阶段 3：黑夜
GM 依次唤醒角色（屏幕对玩家显示相应过程的叙事文本）：

1. **狼人商议**：若存活狼人 ≥2，它们进行一次简短"私聊"（几轮对话）共同决定目标；只剩 1 狼时独自决定。投票以结构化输出（`{"target": "Kai", "reason": "..."}`）提交。
2. **预言家查验**：选择目标，GM 通过 prompt 告知结果"好人/狼人"，写入 memory。
3. **女巫**：GM 告知"今晚 X 被袭击，是否使用解药？"，之后"是否使用毒药？"。

所有夜间决策都要求 bot 先输出 `thinking` 字段（简短推理）再输出 `decision`，推理过程在 UI 上以"……"延迟动画表现，增强悬念。

### 5.6 阶段 4：黎明 —— 结算与放逐投票
1. GM 宣布夜间结果（"昨晚 Kai 死了"），处理猎人开枪等连锁。
2. **放逐讨论**：回到白天自由活动模式（较短，默认上限 20 条对话），讨论谁可疑。
3. **投票**：所有存活者（含 bot、玩家）投票。bot 投票 prompt 包含：角色、memory 摘要、白天所有对话记录（截断）、personality。允许平票 PK（平票者再发言一轮后重投）。
4. 公布票数，最高票者出局并发表遗言。

### 5.7 胜负判定
- 狼人全灭 → 好人胜。
- 狼人数量 ≥ 好人数量 → 狼人胜。
- 每轮结束后 GM 检查并宣布游戏结束；bot 生成一句结算感言（狼人会嘲讽或装遗憾）。

## 6. Bot Prompt 工程设计（核心）

### 6.1 Context 组装（每次调用前由服务端构建）

```
[SYSTEM]
你正在玩一局狼人杀。你的身份是【{role}】。{角色私密信息，如队友名单}
{若玩家是人类：坐在你对面的人类玩家叫 "玩家"。}

[游戏规则简述] (~150字)
白天自由交谈→投票放逐；黑夜各角色行动；狼人杀光好人或好人投光狼人即分胜负。

[你的性格] (~200字, 从 personality 文件渲染)
名字：露娜。话很少，温柔迟疑……小动作习惯：思考时用笔尖点桌面。
{若当前在撒谎任务：注意，你说谎时会有破绽：语速突然变快、避免直视。}

[你的记忆] (~400字, 从 memory 文件摘要渲染)
本局身份：狼人，队友是 Marcus。
第1天：白天我假装支持 Yuki……今晚计划刀 Kai。
跨局记忆：Kai 上局差点识破我，这局保持警惕。
你对各玩家的信任度：Kai -0.3, Yuki +0.1, Marcus +0.5。

[当前对话记录] (最近 {K} 条, 每条 ≤100字, K≈15)
...

[当前任务]
现在是白天自由活动。请决定你的下一个行动。
```

**预算控制**：总 prompt ≤ 4k token（7B 模型舒适区）。memory 超预算时按 3.2 规则先压缩；对话记录只保留最近 K 条，更早的由 GM 维护一份"本日摘要"（约 200 字）注入。

### 6.2 结构化输出
所有关键决策要求 JSON 输出，例如白天行动：

```json
{
  "thinking": "我想试探一下 Kai，他今天太安静了（≤80字）",
  "action_type": "question | gesture | statement | response",
  "target": "Kai",
  "content": "唔……Kai，你今天好像一直没什么话想说？",
  "gesture": null,
  "memory_update": "我公开质疑了 Kai，观察他的反应"
}
```

服务端解析 JSON；解析失败则重试一次（带"只输出合法 JSON"的纠正 prompt），再失败则使用安全兜底（随机小动作）。

### 6.3 生成参数
- 白天闲聊：`temperature 0.8`（活泼多变）
- 投票/夜间决策：`temperature 0.3`（稳定理性）
- `num_ctx` 按模型设定，超时 30s，重试 1 次。

## 7. Game Master（GM）模块设计

GM 是服务端的一段确定性逻辑（非 LLM），职责：
- 状态机推进、角色分配、死亡结算、胜负判定。
- **行动队列调度**（5.3）。
- **话题枯竭检测**：统计最近行动步中实质对话比例。
- **对话上限计数**。
- **LLM 调用编排**：组装 prompt、调 Ollama、解析 JSON、写入 memory、触发压缩。
- **裁判信息分发**：验人结果、死亡通知、票数统计等只发给该知道的 bot。
- 可选：GM 旁白用 LLM 生成氛围文本（"夜色降临，村庄陷入寂静……"）。

## 8. UI/UX 设计

### 8.1 大厅界面
- 左侧：personality 文件列表（缩略卡显示名称/话多程度/风格标签），支持新建（表单编辑器）、编辑、删除。
- 中央：对局配置——人数滑块、角色板子预览、bot 槽位 ↔ personality 下拉绑定。
- "开始游戏"按钮。

### 8.2 游戏主界面
```
┌──────────────────────────────────────────────┐
│  第 2 天 · 白天 · 自由活动        [进入黑夜 ➜] │
├──────────────┬───────────────────────────────┤
│   圆桌头像区  │        对话/事件流              │
│  (bot 状态:   │  Marcus: 我觉得昨晚的事不简单…    │
│   存活/死亡)  │  【小动作】露娜 轻轻搅动着咖啡     │
│              │  👤 你 → Yuki: 你昨晚在哪？       │
├──────────────┴───────────────────────────────┤
│  观察 | 提问 | 发表看法 | 动作 | 提议黑夜          │
└──────────────────────────────────────────────┘
```
- 对话流区分渲染：bot 发言（带名字颜色）、小动作（斜体灰字，可高亮破绽）、GM 旁白（居中横幅）、系统结算。
- 观察面板：点击 bot 显示其最近动作时间线，"破绽"用 ⚠ 标记。
- 夜晚：画面变暗，仅展示 GM 叙事 + 玩家的夜间操作（若有角色能力）。

### 8.3 节奏与反馈
- bot 思考时显示"正在思考…"（其 `thinking` 摘要在停顿后以"看起来在犹豫"等描述呈现，或直接展示，由配置决定——**展示 bot 的思考会大幅帮助玩家推理，建议默认只展示动作结果**）。
- 每轮对话在页面底部显示进度（"本轮对话 23/50"）。

## 9. 边界情况与容错

| 情况 | 处理 |
|------|------|
| Ollama 未启动/模型不存在 | 开局前健康检查，失败则提示并阻止开局 |
| LLM 输出非 JSON | 重试一次 + 兜底动作（小动作），记日志 |
| LLM 超时 | 30s 超时 → 重试 → 兜底"（沉默）" |
| bot 提及不该知道的秘密（幻觉穿帮） | GM 过滤：输出内容中出现非本人应知的角色信息时，替换为兜底文本 |
| 玩家中途退出 | 服务端保留对局存档（memory 写入磁盘），可"继续游戏" |
| 平票 | 平票者各 30 秒遗言式陈述，再投一次；再平则本轮无人出局 |
| 连续游戏 | memory 跨局保留；玩家可在大厅选择"重置所有 bot 记忆" |

## 10. 开发路线图（建议）

1. **MVP（1–2 周）**：6 人局（2 狼 + 1 预言家 + 3 村民）、白天固定轮流发言简化版、personality 文件硬编码 3 个、memory 仅当前局。
2. **v0.2**：自由行动队列 + 小动作系统 + 观察机制；personality 编辑器 UI。
3. **v0.3**：女巫/猎人/女巫等完整板子、黑夜 LLM 私聊、投票结构化输出。
4. **v0.4**：memory 跨局摘要 + 信任账本；对话压缩管线。
5. **v1.0**：破绽观察系统打磨、夜晚氛围叙事、对局回放日志、配置面板。
